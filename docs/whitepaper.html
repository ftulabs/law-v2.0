Abstract

Abstract

The UN ESCAP Regulatory Digital Trade Integration Index (RDTII) scores every economy against dozens of digital-trade indicators. Compiling it is manual, slow, and hard to reproduce: an analyst must, for each economy and indicator, find the right statute across bespoke government portals, read the operative clause (often a scanned PDF, sometimes in another language), interpret whether it satisfies the indicator, and cite it precisely.

VeriTrade automates that workflow end-to-end. Given only an economy and a regulatory pillar, it autonomously discovers relevant primary legislation on official portals (no seed URLs, no hardcoded law names), extracts article-level text from HTML, text PDFs and scanned PDFs, and maps each provision to the exact RDTII indicator using sibling-aware LLM legal reasoning — attaching a 100%-verbatim snippet, an article-level citation, a source URL, a four-signal confidence score, and a full audit trail. It runs on a CPU, at ~$0.07 per economy (or $0 on an open-weight stack), and every claim it makes is built to be reproduced and checked.

This paper is an audit surface: the interactive figures reproduce the production code exactly — watch the pipeline run, drive the confidence formula, and the cost model — so you can check the claims, not just read them.

§1

Why this is hard — and manual vs automated

Building the index at scale runs into six structural obstacles: portals are scattered and unindexed (Singapore's is token/JS-gated, Malaysia's is barely indexed by Google, Australia's is a single-page app); many are bot-protected (HTTP 403 to a plain crawler); formats are mixed (HTML, text PDFs, scanned image-only PDFs); statutes are multilingual; one indicator is buried across several acts; and every citation must be verifiable against the official source.

§2

Objectives & contributions

VeriTrade replicates the professional researcher's workflow — reproducibly, on a standard CPU, with no vendor lock-in:

  1. Discover — locate relevant primary legislation on official portals, live, with no seed URLs and no hardcoded law names.
  2. Extract — parse article-level text from HTML, text PDFs and scanned PDFs (real OCR, measured CER < 5%).
  3. Map — assign each provision to the correct indicator using LLM reasoning that sees every sibling indicator.
  4. Verify & cite — 100%-verbatim snippet, article-level citation, source URL, and a confidence score; low-confidence rows go to human review.
  5. Deliver — the exact official 13-column CSV plus a machine-auditable JSON.
Design principles. Auditable over opaque · reproducible over one-off · swappable components (LLM / OCR) over lock-in · precision with an explicit human-review safety net.

§4

Zone 1 — autonomous discovery & bot-resistant fetching

Discovery never uses a law name as a query. It builds country-agnostic queries from the indicator definitions — concept phrases plus short title-robust fragments — and fires them at the portal(s):

EconomyPortalDiscovery strategy
Singaporesso.agc.gov.sgPortal-scoped web search (Serper → keyless fallback); token/JS-gated pages cleared by a real-browser fetch.
Australialegislation.gov.auOfficial OData API for titles, plus a content-based full-text lane that finds laws by what their clauses say — then verifies each is in-force.
Malaysialom.agc.gov.myThe portal's own acts catalogue (Google barely indexes it), matched on bilingual titles, plus sectoral Codes of Practice.
Why content-based discovery matters. A title match finds the Privacy Act; it never finds Australia's Consumer Data Right Rules, whose relevance is in their obligations, not their names. VeriTrade's obligation-phrase lane surfaces exactly these, then drops repealed acts and bills against the official register — the concrete answer to the rubric's ban on a "baked corpus": it finds laws by what they regulate. Fetching uses Scrapling's real-browser TLS/JA3 fingerprint to clear WAFs that 403 a plain crawler.
§5

Zone 2a — extraction, OCR & measured fidelity

Each document is classified text-layer or scanned. MarkItDown reads text PDFs; RapidOCR/PaddleOCR handle image-only scans, and the Character Error Rate is measured against a ground-truth sidecar. The result on the bundled gazette scan is dramatic:

Scale 0–5%. Measured CER 1.11% sits at ~22% of the way to the fail bar — well inside spec. Verbatim, country-aware chunking then splits the clean text into one provision per chunk, preserving exact source characters.

§6

Zone 2b — hybrid retrieval

Retrieval fuses three signals: BM25 (lexical), a multilingual bi-encoder (paraphrase-multilingual-MiniLM-L12-v2) for semantic recall, and a cross-encoder rerank for precision.

Grade-all policy. For small corpora (≤ 80 provisions) every provision is graded against every indicator — retrieval ranking is a signal, not a gate. This protects non-English recall: even if the English-only reranker mis-orders a Malay provision, the grader still sees it.
§7

Zone 2c — mapping via sibling-aware LLM reasoning

Mapping is not a black-box classifier. For each (provision, target indicator) pair the model receives the indicator's legal test, its scope, and every sibling indicator's legal test, then reasons in explicit steps: state the operative rule (ignoring definitions/recitals) → does it satisfy the target's test? → is a sibling a better fit? → relevant or reject?

Conservative by default. When unsure, the model rejects — a precise miss beats a wrong over-assignment. Borderline rows are surfaced to the review queue, never silently accepted or dropped.

§9

Verifiable evidence — the anti-hallucination chain

A citation is worthless if the quote was invented. VeriTrade guarantees fidelity by construction, in five steps:

1
Copied, not generated. The verbatim snippet is copied from the fetched source text — the LLM never writes it.
2
Grounding check. An automatic check confirms the snippet actually occurs in the source document.
3
Topical guard. A snippet with none of the pillar's concept vocabulary is flagged as likely off-topic (and capped).
4
Traceable source. The source URL points to the law on the official portal; the JSON keeps the surrounding context.
5
Confidence gate. Every row carries a score; < 0.85 → review, < 0.60 → quarantine.

§12

Zone 3 — restrictiveness scoring (optional)

Beyond mapping, VeriTrade can assign each measure an RDTII raw score of 0 / 0.5 / 1 (light / partial / heavy) with a one-line justification, quoted from the official criteria, then roll up to one score per indicator.

Polarity gotcha (handled). For 7.1 (comprehensive data-protection) and 7.2 (dedicated cybersecurity) the polarity is inverted: having a strong horizontal framework scores 0. The roll-up takes the minimum across measures for those two indicators and the maximum for all others.

The score never touches the official 13-column submission CSV — it lives in a separate *_scored.csv and in the JSON, so programmatic validation of the submission is never broken. See NOTES_FOR_JUDGES.md for our open question to the judges on where a score column is expected.

§14

Reproducibility & the two paths

A 3-tier cache (fetched documents, embeddings, full results) makes a chosen run replay identically and repeat runs free. The live path crawls the official portals (what judges grade); the offline sample path runs on a bundled corpus with no network. Both share the same code, so the offline run is an honest preview and a graceful fallback.

# live (scored)
python main.py --economy Singapore --pillar 6 --live --llm openrouter
# offline sample (reproducible)
python main.py --economy Singapore --pillar 6
# dashboard
streamlit run frontend/app.py
§15

Limitations & honesty statement

  • Live crawling is functional but needs Playwright auto-escalation for the most JS-heavy / token-auth pages.
  • The LLM grader is stochastic — borderline definitional clauses can flip; the review queue and result cache mitigate.
  • The mock (offline) grader is lexical and can confuse close indicators — always use a real LLM for a submission.
  • Confidence scores are relative, not calibrated probabilities.
  • Multilingual retrieval is general-domain; for non-English text the grade-all policy protects recall, and the concept-vocabulary guard is currently English.
  • Indicator legal tests are our interpretation of the RDTII methodology — review pending rows before submission.
§16

Scalability & future work

  • More economies — add a portal domain; discovery generalises. Finals targets plug in the same way.
  • More languages — swap the reranker to BAAI/bge-reranker-v2-m3 and add a translation × LLM cross-check with bilingual snippet tracking.
  • More domains — the indicator layer is data-driven; add other RDTII pillars by defining their legal tests and query terms.
  • Real-time monitoring — scheduled re-crawls diff against the cache to flag amended or new laws.
Value. For ESCAP: faster, reproducible, auditable RDTII refreshes at a fraction of manual cost. For governments and businesses: quicker access to authoritative, cited digital-trade rules. For researchers: a transparent, open-source base.
